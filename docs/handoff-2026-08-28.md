### `totalCostJeon` 문자열 계약 — 실물 확인

```json
{"batchId": "...", "instCode": "FALH", "channel": "sms", "billable": true,
 "countBasis": "ACCEPTED", "totalCount": 1, "successCount": 1,
 "unitCostJeon": 900, "totalCostJeon": "900", "priceVersion": null}
```

- `totalCostJeon` 이 **따옴표 있는 문자열**이다. 숫자로 나갔으면 플랫폼이 전량 400 이고

- `unitCostJeon: 900` 은 **2단계 폴백**(`inst_data_cs`)에서 온 값. `priceVersion=null` 이 그 증거다

## 다음 세션 시작점 (우선순위순)

### 1. 단가 연동 2차 — **선행: MediCast dev 접속 정보 확보**

필요한 것 두 개. **저장소·문서에 값을 적지 말 것.**

- `CSM_PRICE_PLATFORM_BASE_URL` (MediCast **dev**)
- `CSM_PRICE_PLATFORM_API_KEY`

확보하면 순서는 [prod-deploy-checklist.md](prod-deploy-checklist.md) §9.2~9.4 그대로다.

```bash
# ① 켜기 전에 반드시 대조 (§9.3). 붙인 뒤에는 이미 덮어쓴 뒤다.
curl -s -H "X-Internal-Api-Key: $CSM_PRICE_PLATFORM_API_KEY" -H "Accept: application/json" \
  "$CSM_PRICE_PLATFORM_BASE_URL/internal/prices?instCode=COHS" | python3 -m json.tool
```

- 기관코드가 **대문자**인가 / 금액이 **전 단위**인가(9.6원이면 `960`)를 눈으로 본다
- 하나라도 어긋나면 **주입하지 않는다.** 플랫폼에서 먼저 고친다

> ⛔ 켜는 순간 `PlatformPriceCache.store()` 가 `platform_price_cache` **와 `inst_data_cs` 를 같이**
> 덮어쓴다. 잘못된 값이 들어오면 URL 을 다시 빼도 **2단계 폴백에 남아 그대로 청구된다.**

주입 위치는 dev 의 **`/usr/local/tomcat10/bin/setenv.sh`** 이고, csm 은 공용 Tomcat 의 war 라
**Tomcat 전체 재시작이 필요하다** (war auto-reload 로는 env 가 안 먹는다).

## 검증에 쓴 명령 (그대로 재사용 가능)

dev DB 계정은 **`csdev`** 다. `mysql` 을 인자 없이 부르면 인증 실패로 **조용히** 끝난다.

```bash
ssh root@49.247.42.59 'ls -ld --time-style=full-iso /usr/local/tomcat10/webapps/csm /usr/local/tomcat10/webapps/csm.war; echo ---START---; grep -ah "Started ServletInitializer" /usr/local/tomcat10/logs/catalina* | tail -3; echo ---PRICEPOLL---; grep -ac "price-poll" /usr/local/tomcat10/logs/catalina*; echo ---ENV---; grep -E "CSM_PRICE_PLATFORM_(BASE_URL|API_KEY)" /usr/local/tomcat10/bin/setenv.sh || echo "NOT SET"'
```

```bash
ssh -t root@49.247.42.59 "mysql -u csdev -p -e \"SELECT batch_id, inst_code, source, attempts, next_retry_at, sent_at, failed_reason, created_at, payload FROM csm.sms_usage_outbox ORDER BY created_at DESC LIMIT 2\G\""
```

`sms_usage_outbox` 에는 **`status` 컬럼이 없다.** 상태는 `sent_at` / `next_retry_at` /
`failed_reason` 로 표현한다. PK 는 `batch_id` 이고 `id` 컬럼도 없다.
