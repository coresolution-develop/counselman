## 1. 이 세션의 핵심 — 검증을 안 했으면 계속 유실되고 있었다

"Phase 1-B 잔여 검증"으로 시작했다가 **운영 문자 7건이 조용히 유실되고 있던 것**을 발견해
수정·배포까지 마쳤다. 스키마·인덱스 확인 같은 형식적 점검이 아니라 **실제 데이터를 본 것**이
발견 경로였다.

**증상**: 접수는 `code=1000 success`로 정상, 0~1초 뒤 결과 리포트가 `9020`으로 실패.
화면에는 "전송 완료"로 뜨지만 실제로는 나가지 않는다. `ERROR`는 발송내역 기본 필터에서
제외되므로 **사용자도 목록에서 볼 수 없다.**

**원인**: `SmsMessageTypeResolver.subjectFor()`가 본문 앞 20자를 그대로 LMS 제목으로 썼다.
본문이 짧은 인사말로 시작하면(`건강하세요~\n효사랑…`) **제목에 줄바꿈이 들어가고**, 비즈뿌리오가
이를 즉시 거부한다. 구 경로(inpatient 화면)는 제목을 아예 보내지 않아 2,480건이 무사했고,
Phase 1-B에서 제목을 일원화하면서 드러났다.

**근거**: 실패 7건 전부 앞 20자에 개행 포함(`has_newline=1`), 성공한 1건만 `0`. 100% 일치.
같은 본문(335자)이 08-13 구 경로에서는 `전송완료`, 08-14 신규 경로에서는 `ERROR`.

**수정**: 개행·탭을 공백으로 바꾸고 연속 공백을 접은 뒤 20자로 자른다(`d6b078c`).
회귀 테스트 3개 추가.

## 5. 함정 목록 — 다음 사람이 밟지 말 것

1. **`ERROR` 상태는 발송내역 화면에 안 보인다.** `VISIBLE_STATUS_FILTER`가 실패를 숨긴다.
   "문자가 안 갔다"는 문의가 오면 화면이 아니라 **DB를 직접 봐야 한다.**

2. **접수 성공(`code=1000`)은 발송 성공이 아니다.** 전달 결과는 콜백의 `result` 코드로만 알 수 있다.
   `sms_batch.success_count`도 접수 기준이라 실제 전달과 다를 수 있다.

3. **중첩 env 폴백은 바깥 변수가 있어도 안쪽이 평가된다.**
   `${MEDIPLAT_DATASOURCE_URL:${SPRING_DATASOURCE_URL}}`에서 앞 변수를 채워도
   `SPRING_DATASOURCE_URL`이 없으면 `PlaceholderResolutionException`으로 죽는다.
   **배포 전 0-0 env 대조를 반드시 거칠 것.**

4. **prod 푸시만으로는 배포되지 않는다.** staging 적재까지가 끝이고 적용은 02:30 타이머다.
   즉시 반영하려면 `systemctl start csm-next-deploy.service`.
   **새벽 자동 적용에 맡기면 실패해도 아침까지 아무도 모른다.**

5. **`catalina.out`은 2026-05-08 이후 갱신되지 않는 낡은 파일이다.** csm 로그는 journald,
   mediplat 로그는 `/opt/csm-next/logs/mediplat.log`(유닛이 파일로 리다이렉트).
   `journalctl -u mediplat-next`에는 systemd 메시지만 보인다.

6. **`Restart=always`가 크래시 루프를 가린다.** 상태가 `failed`가 아니라
   `activating (auto-restart)`로 보인다. `active`가 아니면 정상이 아니다.

7. **백업 파일명의 `<TS>`는 백업 시각, mtime은 빌드 시각이다.**
   되돌릴 때 mtime으로 고르면 엉뚱한 버전을 집는다. **이름 기준 최신**을 쓸 것.

8. **ImageMagick 내부 SVG 렌더러는 `fill="none"` + stroke 도형을 그리지 않는다.**
   아이콘을 PNG로 뽑을 때 빈 이미지가 나오면 이것이다. 채움 경로(even-odd)로 바꿀 것.
