# 문자 단가는 어디서 관리하나 — 사내 운영자 안내

작성일: 2026-08-27 · 대상: 코어솔루션 운영 담당자 · 관련 티켓: CSM-2, CSM-3

> **병원 담당자용 안내가 아니다.** 병원 계정은 원래 단가를 수정할 수 없었고,
> 이번 변경으로 병원 화면에서 달라지는 것은 없다.

---

## 1. 한 줄 요약

**문자 단가는 이제 MediCast 에서 관리한다.** csm(`/core/smssetting`)에서는 **볼 수만 있다.**

---

## 2. 무엇이 달라졌나

| | 이전 | 지금 |
|---|---|---|
| 단가를 정하는 곳 | csm `/core/smssetting` | **MediCast 관리자 화면** |
| csm 화면 | 단가등록 / 단가수정 버튼 | **버튼 없음. 표시만** |
| 반영까지 걸리는 시간 | 즉시 | **최대 5분** (csm 이 5분마다 가져간다) |
| 전 기관 일괄 변경 | csm 에서 한 번에 가능했다 | **없앴다** (아래 4번) |

---

## 3. 단가를 바꾸려면

1. **MediCast 관리자 화면**에서 해당 기관 단가를 수정한다
2. **최대 5분** 기다린다 — csm 이 5분마다 가져간다. 즉시 반영은 없다
3. csm `/core/smssetting` 의 **"단가 수신"** 열에서 반영을 확인한다

### "단가 수신" 열 읽는 법

| 표시 | 뜻 | 할 일 |
|---|---|---|
| `v7  3분 전` | 정상. 3분 전에 v7 을 받았다 | 없음 |
| `⚠ v7  3시간 전` | **15분 넘게 못 받았다** | 5번으로 |
| `-  수신 이력 없음` | 아직 한 번도 못 받았다 | 6번으로 |

> **왜 시각까지 보여주나.** "MediCast 에서 관리합니다" 만 적어 두면
> 폴링이 멈춰도 화면이 똑같아 보인다. 그러면 낡은 단가로 청구되는 것을 알 수 없다.
> **시각이 오래된 것 자체가 신호다.**

---

## 4. 없어진 기능 — 전 기관 일괄 단가 변경

이전 "전체 단가 등록" 은 **`WHERE` 절이 없는 UPDATE** 였다.
한 번 저장하면 **모든 병원 단가가 한꺼번에** 바뀌었고, 이전 값을 남기지 않아 되돌릴 수 없었다.

지금은 MediCast 에서 **기관별로** 설정한다. 여러 기관을 바꿔야 하면 기관 수만큼 반복한다.
번거롭지만, 한 번의 실수가 전 병원에 퍼지지 않는다.

---

## 5. ⚠ 표시가 떴을 때

단가를 15분 넘게 못 받았다는 뜻이다. **발송은 계속되고 있고, 마지막으로 받은 단가로 청구된다.**

확인 순서:

1. **MediCast 관리자 화면**에서 해당 기관 배포 상태를 본다
   - `불일치` → 플랫폼이 보낸 값을 csm 이 거부했다. 거부 사유와 값이 화면에 있다
   - `폴링 끊김` → csm 이 플랫폼에 닿지 못하고 있다
2. csm 로그를 본다

   ```bash
   journalctl -u csm --since '1 hour ago' | grep -i 'price-poll\|sms-price'
   ```

   | 로그 | 뜻 |
   |---|---|
   | `연결 실패 — 이전 단가를 유지합니다` | 플랫폼에 못 닿는다. 네트워크·플랫폼 상태 확인 |
   | `거부 — ... (값 N전)` | 플랫폼 값이 업무 상한을 넘었거나 형식이 틀렸다. **플랫폼에서 고친다** |
   | `PLATFORM_CACHE_EMPTY` | 한 번도 못 받았다. 6번으로 |

3. **급하지 않으면 그대로 둔다.** 이전 단가로 발송이 계속되는 것은 설계된 동작이다.
   플랫폼이 살아나면 5분 안에 자동 정정된다

**플랫폼이 죽었고 단가가 틀린 상태라면** — 그때만 수동 개입이다.
절차: [`docs/prod-deploy-checklist.md`](prod-deploy-checklist.md) **§9.5 비상 절차**

> ⚠️ **csm DB 를 임의로 고치지 않는다.** 플랫폼이 살아 있으면 다음 폴링이 덮어쓴다.
> §9.5 는 **URL 제거 → 재시작 → SQL 수정** 순서를 지켜야 한다. 순서를 틀리면 되돌아간다.

---

## 6. 전 기관이 "수신 이력 없음" 일 때

**연동이 아직 켜지지 않은 것이다.** 오류가 아니다.

CSM-3 은 `CSM_PRICE_PLATFORM_BASE_URL` **미설정** 상태로 먼저 배포된다.
그 상태에서는 단가가 배포 전과 똑같이 동작한다 (기존 `inst_data_cs` 값 → 프로퍼티 폴백).

연동을 켜는 절차는 [`docs/prod-deploy-checklist.md`](prod-deploy-checklist.md) **§9** 에 있다.
**플랫폼 단가를 눈으로 대조한 뒤에 켠다** — 잘못된 값으로 켜면 폴백까지 오염된다.

---

## 7. 자주 나오는 질문

**Q. 급한데 5분을 못 기다린다.**
즉시 반영 경로는 만들지 않았다. 플랫폼이 csm 을 호출하는 구조가 되면 두 시스템의 격리가 깨진다.
5분은 상한이고 보통 그보다 빠르다.

**Q. csm 화면에서 임시로 고치면 안 되나.**
안 된다. 버튼도 없고 API 도 410 을 돌려준다.
막지 않았더라도 **다음 폴링이 5분 뒤 덮어쓴다** — 비상 수단으로도 작동하지 않는다.

**Q. 병원에서 "단가 화면이 바뀌었다" 고 물어보면.**
병원 화면(`/rate`)은 바뀌지 않았다. 원래 표시 전용이었고 지금도 그렇다.

**Q. `⚠` 가 떴는데 발송이 멈추나.**
멈추지 않는다. 마지막으로 받은 단가로 계속 나간다.
문제는 "멈춤" 이 아니라 **"낡은 값으로 청구될 수 있음"** 이다.

**Q. 15분 기준은 어디서 나왔나.**
폴링 주기(5분)의 3배다 — 2회 연속 실패까지는 일시적 오류로 본다.
MediCast 의 "폴링 끊김" 판정과 **같은 기준**이라 두 화면이 같은 상황을 다르게 말하지 않는다.
바꾸려면 `CSM_PRICE_STALE_MINUTES` 와 플랫폼의 `PRICE_POLL_STALE_MINUTES` 를 **같이** 조정한다.
